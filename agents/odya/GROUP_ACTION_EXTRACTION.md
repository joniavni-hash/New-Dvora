## מצב: Group Action Extraction

**מתי:** כשקבוצה מסיימת דיון פעיל או יש צורך לחלץ משימות
**מטרה:** זיהוי מדויק של פעולות, אחראים ודדליינים

---

## אלגוריתם חילוץ משימות

### שלב 1: זיהוי Action Verbs
חפשי בהודעות:
- **מילות פעולה ישירות:** "אני אבדוק", "תכין", "נשלח", "תתקשר" 
- **התחייבויות:** "אני אקח על זה", "זה עליי", "אני אטפל"
- **הטלת משימות:** "תוכל לבדוק?", "בבקשה תכין", "מי יכול לטפל"

### שלב 2: זיהוי אחראים
**חוקי זיהוי:**
1. **אחראי מפורש:** "יוני יבדוק את זה"
2. **אחראי משתמע:** "אני אבדוק" ← מי שכתב
3. **אחראי מותנה:** "אם מתן פנוי, הוא יטפל"
4. **לא ברור:** סמן כ-"TBD"

### שלב 3: זיהוי דדליינים
**פורמטים נפוצים:**
- זמן מפורש: "עד מחר", "עד יום ראשון", "עד 28.03"
- זמן יחסי: "עד סוף השבוע", "תוך יומיים"
- אירוע מותנה: "לפני הפגישה עם הלקוח"
- לא צוין: "ASAP" או ללא דדליין

---

## פורמט פלט

### עבור כל פעולה שזוהתה:
```json
{
  "action": "בדיקת תקציב לקמפיין מרקטינג",
  "owner": "שרה",
  "owner_confidence": 0.9,
  "deadline": "2026-03-28",
  "deadline_type": "explicit",
  "context": "שרה אמרה: 'אני אבדוק את התקציב עד יום חמישי'",
  "message_timestamp": "2026-03-24T14:30:00Z",
  "priority": "medium",
  "status": "new"
}
```

### רמות Confidence:
- **0.9-1.0:** מפורש וברור ("יוני אמר שהוא יעשה X עד מחר")
- **0.7-0.8:** סביר מאוד ("נראה שמתן אמר שהוא יטפל")  
- **0.5-0.6:** משוער ("מישהו צריך לבדוק את זה")
- **0.0-0.4:** לא לחלץ

## דוגמאות חילוץ

### דוגמא 1: הצלחה
**הודעה:** "יוני, תוכל לבדוק את המחירים של הספק החדש עד יום ראשון?"
**חילוץ:**
```json
{
  "action": "בדיקת מחירי ספק חדש",
  "owner": "יוני",
  "owner_confidence": 1.0,
  "deadline": "2026-03-30", 
  "deadline_type": "explicit",
  "priority": "medium"
}
```

### דוגמא 2: חלקי
**הודעה:** "מישהו צריך לטפל בנושא הביטוח"
**חילוץ:**
```json
{
  "action": "טיפול בנושא ביטוח",
  "owner": "TBD",
  "owner_confidence": 0.0,
  "deadline": null,
  "deadline_type": "none", 
  "priority": "low"
}
```

### דוגמא 3: מותנה
**הודעה:** "אם מתן יהיה פנוי השבוע, הוא יכין את המצגת"
**חילוץ:**
```json
{
  "action": "הכנת מצגת",
  "owner": "מתן",
  "owner_confidence": 0.6,
  "deadline": "2026-03-30",
  "deadline_type": "conditional",
  "context": "מותנה בזמינות מתן",
  "priority": "medium"
}
```

## כללי סינון

### ✅ לחלץ
- פעולות קונקרטיות עם בעלים
- התחייבויות אישיות ("אני אעשה X")
- הטלת משימות ישירות ("תבדוק את Y")
- החלטות שדורשות מעקב

### ❌ לא לחלץ  
- דעות או הערות ("אני חושב ש...")
- שאלות רטוריות ("מי יודע מתי זה יסתיים?")
- תוכניות רחוקות ("בעוד כמה חודשים נצטרך לחשוב")
- אזכורים לפעולות שכבר בוצעו

---

## אינטגרציה עם OPEN_TASKS

### עבור פעולות עם confidence > 0.7:
הוסף אוטומטית ל-`state/OPEN_TASKS.md`:
```markdown
### 🟡 [שם המשימה] — [אחראי]
- opened: [תאריך]
- source: קבוצת [שם קבוצה]
- content: [תיאור המשימה]
- deadline: [דדליין אם יש]
- priority: 🟡 מקבוצה
- followup: כל 3 ימים
```

### עבור confidence < 0.7:
רק דיווח בסיכום, לא הוספה ל-OPEN_TASKS

## איכות חילוץ

### מדדי הצלחה:
- **Precision:** כמה מהפעולות שחולצו אכן משימות אמיתיות
- **Recall:** כמה משימות אמיתיות לא פספסנו
- **Timeliness:** כמה מהרה משימות מזוהות אחרי שנוצרו

### מעקב איכות:
בכל חילוץ, תעד ב-`state/groups/<group_id>.json`:
```json
{
  "extraction_stats": {
    "total_actions_extracted": 15,
    "high_confidence_actions": 12,
    "tasks_added_to_open": 8,
    "last_extraction": "2026-03-24T18:00:00Z"
  }
}
```

## הטיפול במקרי קצה

### כשיש עדכון למשימה קיימת:
"עדכון: בדקתי את הספק, המחיר 500 ש״ח"
→ חפשי משימה קיימת וסמן כהושלמה

### כשיש ביטול משימה:
"ביטלנו את הפגישה עם הספק"  
→ זהה משימות קשורות וסמן כבוטלות

### כשיש העברת משימה:
"מתן לא יספיק, שרה תיקח את זה"
→ עדכן אחראי במשימה קיימת
